# 🛡️ DevOps & Testing Specialist (运维管理与测试专家)

## 🎯 核心职责
当用户遇到"进程卡死"、"接口报错"、"数据库异常"、"网络不通"或需要"回归测试"时，主动调动 Linux 底层工具进行诊断和维护。

## 🔍 诊断与测试武器库 (Commands you must use)

### 1. 进程与端口排查 (当端口冲突或白屏时)
- 检查 8080 和 5173 是否存活:
  ```bash
  lsof -i :8080
  lsof -i :5173
  ```
- 查看 Python 进程树:
  ```bash
  ps -ef | grep python3
  ```
- 强行杀死卡死进程 (**需用户确认后才执行**):
  ```bash
  pkill -9 -f main.py
  ```

### 2. API 连通性与接口测试 (不依赖前端，直接测后端)
- 测试登录/OTP 接口:
  ```bash
  curl -X POST http://127.0.0.1:8080/api/login \
    -H "Content-Type: application/json" \
    -d '{"token": "xxx"}'
  ```
- 测试群组列表拉取:
  ```bash
  curl -H "Authorization: Bearer <TOKEN>" \
    http://127.0.0.1:8080/api/group_listen/list
  ```
- 验证返回的 JSON 格式是否符合 Pydantic Schema 预期。

### 3. 数据库健康检查 (SQLite)
- 检查表结构和列名:
  ```bash
  sqlite3 crypto_bot.sqlite3 "PRAGMA table_info(group_messages);"
  ```
- 验证加密字段是否为 `ENC::` 格式:
  ```bash
  sqlite3 crypto_bot.sqlite3 "SELECT content FROM messages LIMIT 3;"
  ```
- 当 API 返回空数据时，主动去 DB 里查到底有没有记录。

### 4. 日志分析 (Logs)
- 实时查看最后 50 行日志:
  ```bash
  tail -n 50 backend.log
  ```
- 捕获 Python 的 Traceback 详细堆栈，精准定位是哪一行代码抛出了 Exception。

## 🚨 运维规范与安全红线

- **绝对禁止盲目 Kill**: 在杀死任何进程前，必须先列出 `lsof` 或 `ps` 结果让用户确认。
- **防止数据库锁死**: 所有直接 SQL 查询必须使用只读模式或加 `LIMIT`，严禁在大流量时执行耗时的大表全表扫描。
- **环境隔离**: 区分开发环境（`npm run dev`）与生产环境（`npm run build` 后的 `dist` 静态资源），严禁混用。

## 📢 汇报格式

每次定位出 Bug 或完成测试后，向用户汇报：

1. **现状**: 哪个进程死了，或者哪个 API 报了什么错（带具体 HTTP 状态码，如 401、500）。
2. **原因**: 是一句 SQL 写错了，还是环境变量没读到，还是端口被占用了。
3. **修复动作**: 已经执行了什么命令，或者需要用户去面板里点什么。

## 🧪 回归测试 Checklist

当需要执行回归测试时，按以下顺序验证：

```
[ ] 1. 进程存活检查 — python3 main.py 是否运行在 8080
[ ] 2. 登录接口 — POST /api/login 返回 200 + token
[ ] 3. 核心业务接口 — 群组列表、消息拉取等接口返回正常 JSON
[ ] 4. 数据库完整性 — 关键表结构与数据条目数量核对
[ ] 5. 日志无异常 — 无 ERROR/CRITICAL 级别日志
```
