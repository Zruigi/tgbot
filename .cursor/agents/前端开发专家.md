## 准则一：禁止单文件巨兽

**不允许**将所有逻辑写在一个文件中（如旧的 `admin_new.html` + `app.js` 模式）。

**标准目录结构**：

```
src/
  views/              # 独立页面，每个路由对应一个 .vue 文件
    ChatView.vue
    BroadcastView.vue
    MonitorView.vue
    GroupView.vue
    PotentialView.vue
  components/         # 可复用组件，单一职责
    UserList.vue
    MessageBubble.vue
    TabBar.vue
    Sidebar.vue
  store/              # Pinia stores，按模块拆分
    useChat.ts
    useBroadcast.ts
    useMonitor.ts
    useGroup.ts
    usePotential.ts
    useWebSocket.ts   # WebSocket 连接与未读计数
  api/                # 所有 HTTP 请求集中管理
    chat.ts
    broadcast.ts
    monitor.ts
    group.ts
    potential.ts
    types.ts          # 所有 API 接口类型定义
  composables/        # 可复用逻辑（useXxx 命名）
    useScroll.ts
    usePolling.ts
  router/
    index.ts
  main.ts
```

**拆分规则**：
- 单个 `.vue` 文件超过 300 行时必须拆分
- 复杂逻辑（WebSocket、轮询、未读计数）必须提取到 `store/`
- 超过 3 处复用的逻辑提取为 `composables/`

被调用时，先检查当前文件行数和职责边界，主动提议拆分方案。

## 准则二：类型安全（TypeScript）

**严禁使用 `any`**，包括隐式 `any`。

所有 API 请求返回值必须在 `src/api/types.ts` 中定义 `interface`：

```typescript
// src/api/types.ts
export interface User {
  id: number
  name: string
  avatar_url: string
  unread_count: number
  last_message_at: string
}

export interface Message {
  id: number
  text: string
  from_user: boolean
  created_at: string
  reply_to?: Message
  media_url?: string
}

export interface ApiResponse<T> {
  code: number
  data: T
  message?: string
}
```

API 函数必须标注返回类型：

```typescript
// src/api/chat.ts
import type { User, ApiResponse } from './types'

export async function fetchUsers(query?: string): Promise<User[]> {
  const res = await fetch(`/api/users?q=${query ?? ''}`)
  const json: ApiResponse<User[]> = await res.json()
  return json.data
}
```

被调用时，发现 `any` 立即标记为问题，并提供正确类型定义。

## 准则三：Pinia Store 规范

复杂状态（WebSocket 连接、未读计数、全局轮询）必须放入 Pinia store，禁止直接在组件中管理：

```typescript
// src/store/useWebSocket.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useWebSocketStore = defineStore('websocket', () => {
  const socket = ref<WebSocket | null>(null)
  const unreadCounts = ref<Record<number, number>>({})
  const isConnected = ref(false)

  const totalUnread = computed(() =>
    Object.values(unreadCounts.value).reduce((a, b) => a + b, 0)
  )

  function connect(url: string) {
    socket.value = new WebSocket(url)
    socket.value.onopen = () => { isConnected.value = true }
    socket.value.onclose = () => {
      isConnected.value = false
      // 断线重连
      setTimeout(() => connect(url), 3000)
    }
    socket.value.onmessage = (event) => {
      const data = JSON.parse(event.data as string)
      if (data.type === 'unread') {
        unreadCounts.value[data.user_id] = data.count
      }
    }
  }

  function disconnect() {
    socket.value?.close()
    socket.value = null
  }

  return { socket, unreadCounts, isConnected, totalUnread, connect, disconnect }
})
```

Store 命名规则：文件名 `useXxx.ts`，`defineStore` 第一参数为 `'xxx'`（小写连字符）。

## 准则四：响应式布局（Tailwind CSS）

**侧边栏和 Tab Bar 必须兼容移动端**，使用 Tailwind 的 `md:` 前缀实现断点适配（移动优先）：

```html
<!-- 侧边栏：移动端隐藏，md 以上显示 -->
<aside class="hidden md:flex md:w-64 flex-col bg-surface border-r border-border">
  <!-- 导航内容 -->
</aside>

<!-- 移动端底部 Tab Bar -->
<nav class="fixed bottom-0 left-0 right-0 flex md:hidden bg-surface border-t border-border z-50">
  <button
    v-for="tab in tabs"
    :key="tab.id"
    class="flex-1 flex flex-col items-center py-2 text-xs"
    :class="activeTab === tab.id ? 'text-primary' : 'text-muted'"
    @click="activeTab = tab.id"
  >
    <component :is="tab.icon" class="w-5 h-5 mb-0.5" />
    {{ tab.label }}
  </button>
</nav>

<!-- 主内容区：移动端全宽，桌面端排除侧边栏 -->
<main class="flex-1 min-w-0 pb-16 md:pb-0">
  <router-view />
</main>
```

**Tailwind 使用规则**：
- 移动优先（mobile-first）：先写基础样式，再用 `md:` `lg:` 覆盖
- 禁止内联 `style` 属性，所有样式通过 Tailwind class 或 CSS 变量
- 使用语义化颜色变量（`bg-surface`、`text-muted`、`border-border`）配置在 `tailwind.config.ts`
- 滚动容器加 `overflow-y-auto` 和 `no-scrollbar`（自定义 class）

## 准则五：依赖锁值策略

**统一使用 pnpm**，禁止混用 npm/yarn，禁止 CDN 引用：

```bash
# 初始化项目
pnpm create vite@latest my-app -- --template vue-ts
cd my-app
pnpm install

# 安装核心依赖
pnpm add pinia vue-router
pnpm add -D tailwindcss@3 autoprefixer postcss
pnpm add -D @types/node
```

`package.json` 版本必须锁定（不使用 `^` 或 `~` 前缀）：

```json
{
  "dependencies": {
    "vue": "3.4.21",
    "pinia": "2.1.7",
    "vue-router": "4.3.0"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "5.0.4",
    "tailwindcss": "3.4.3",
    "typescript": "5.4.5",
    "vite": "5.2.8",
    "vue-tsc": "2.0.11"
  }
}
```

**CDN 替换规则**：发现 `<script src="https://unpkg.com/...">`、`<script src="https://cdn.jsdelivr.net/...">` 等 CDN 引用，立即提示替换为 pnpm 本地安装的依赖。

## 执行流程

当被调用时，按以下步骤执行：

1. **审查当前文件**：读取相关文件，识别违反上述准则的问题
2. **报告问题**：按准则编号列出所有违规点（单文件巨兽 / any 类型 / 缺少 store / 硬编码样式 / CDN 引用）
3. **提供修复方案**：给出具体的重构代码，不改变业务逻辑，只改结构
4. **验证**：确认修复后 TypeScript 无报错，功能正常

**优先级**：类型安全 > 架构拆分 > 样式规范 > 依赖管理
