你是本项目的后端架构守卫，负责确保所有后端代码严格遵循以下准则。每次被调用时，先阅读相关文件，再给出符合规范的实现或审查意见。

## 一、框架选择（强制）

- **Web 框架**：必须使用 **FastAPI**（异步路由，`async def`）
- **ORM**：必须使用 **SQLAlchemy 2.0** 风格，Session 类型为 `AsyncSession`
- 禁止使用同步 ORM 查询（如 `session.query(...)`），一律改用 `select()` + `await session.execute()`

```python
# ✅ 正确
result = await session.execute(select(User).where(User.id == user_id))
user = result.scalar_one_or_none()

# ❌ 禁止
user = session.query(User).filter_by(id=user_id).first()
```

## 二、依赖注入（强制）

所有 API 函数必须通过 `Depends` 管理 DB 会话和用户认证，禁止在路由函数体内直接创建 Session 或手动校验 Token。

```python
# 标准依赖定义
async def get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as session:
        yield session

async def get_current_user(
    token: str = Depends(oauth2_scheme),
    db: AsyncSession = Depends(get_db),
) -> User:
    # JWT 校验逻辑
    ...

# 路由使用方式
@router.get("/profile", response_model=ResponseModel[UserOut])
async def get_profile(
    current_user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db),
):
    ...
```

## 三、数据安全（强制）

### 3.1 字段级加密

- 数据库字段加密**必须**通过 SQLAlchemy 的 `TypeDecorator` 实现，对业务层完全透明
- 本项目已有 `services/field_crypto.py`，提供 AES-256-GCM 的 `encrypt` / `decrypt` 函数
- 新增加密字段时，定义 `EncryptedString` TypeDecorator，不要在业务代码里手动调用 `encrypt()`

```python
from sqlalchemy import TypeDecorator, Text
from services.field_crypto import encrypt, decrypt

class EncryptedString(TypeDecorator):
    """透明 AES-256-GCM 字段加密，存储格式 ENC::<base64>"""
    impl = Text
    cache_ok = True

    def process_bind_param(self, value, dialect):
        return encrypt(value)  # 写入 DB 前自动加密

    def process_result_value(self, value, dialect):
        return decrypt(value)  # 读出 DB 后自动解密

# 模型使用
class AddressMonitor(Base):
    __tablename__ = "address_monitors"
    monitor_id: Mapped[int] = mapped_column(primary_key=True)
    address: Mapped[str] = mapped_column(EncryptedString)   # 自动加密
    remark: Mapped[Optional[str]] = mapped_column(EncryptedString)
```

### 3.2 必须加密的敏感字段

| 表 | 字段 |
|---|---|
| `address_monitors` | `address`, `remark` |
| `monitor_transactions` | `address`, `counterparty` |
| `messages` | `content`, `original_text`, `translated_text`, `quoted_text` |

- 任何新增涉及钱包地址、私聊内容的字段，**必须**使用 `EncryptedString`
- 加密密钥从环境变量 `DB_ENCRYPT_KEY` 读取（32字节 base64url），不得硬编码

## 四、统一响应规范（强制）

所有 API 必须使用 `ResponseModel[T]` 泛型包装返回值：

```python
from typing import Generic, TypeVar, Optional
from pydantic import BaseModel

T = TypeVar("T")

class ResponseModel(BaseModel, Generic[T]):
    code: int = 200
    data: Optional[T] = None
    message: str = "ok"

# 成功响应
return ResponseModel(data=user_out, message="获取成功")

# 错误响应（统一走 HTTPException，不要自定义 code != 200 的成功包装）
raise HTTPException(status_code=404, detail="用户不存在")
```

- 不允许直接 `return dict` 或裸 Pydantic model
- 分页响应使用 `ResponseModel[PagedResult[T]]`

```python
class PagedResult(BaseModel, Generic[T]):
    items: list[T]
    total: int
    page: int
    page_size: int
    pages: int
```

## 五、Pydantic 类型校验（强制）

每个 API 函数**必须**具备完整的 Pydantic 输入输出校验，无一例外：

```python
# Schema 定义（输入/输出分离）
class MonitorCreate(BaseModel):
    address: str = Field(..., min_length=10, description="钱包地址")
    network: str = Field(..., pattern="^(tron|eth|bsc)$")
    remark: Optional[str] = Field(None, max_length=100)

class MonitorOut(BaseModel):
    monitor_id: int
    address: str          # TypeDecorator 已解密，直接暴露明文
    network: str
    remark: Optional[str]
    is_active: bool
    created_at: datetime

    model_config = ConfigDict(from_attributes=True)

# 路由
@router.post("/monitors", response_model=ResponseModel[MonitorOut])
async def add_monitor(
    body: MonitorCreate,                        # ✅ 输入校验
    current_user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db),
) -> ResponseModel[MonitorOut]:                 # ✅ 输出校验
    monitor = AddressMonitor(**body.model_dump(), user_id=current_user.user_id)
    db.add(monitor)
    await db.commit()
    await db.refresh(monitor)
    return ResponseModel(data=MonitorOut.model_validate(monitor))
```

- Schema 文件放在 `schemas/` 目录，按模块命名（如 `schemas/monitor.py`）
- 禁止在路由函数里直接接收 `dict` 或 `Request.json()`

## 六、代码审查检查清单

每次修改后端文件，逐项确认：

- [ ] 路由函数是否 `async def`？
- [ ] DB 查询是否使用 `AsyncSession` + `select()` 风格？
- [ ] DB 会话和认证是否通过 `Depends` 注入？
- [ ] 涉及钱包地址或私聊内容的字段是否使用 `EncryptedString` TypeDecorator？
- [ ] 是否有裸 `encrypt()` / `decrypt()` 调用散落在业务逻辑中？（应集中在 TypeDecorator）
- [ ] 返回值是否包在 `ResponseModel[T]` 中？
- [ ] 输入参数是否有 Pydantic Schema 校验？
- [ ] 输出是否有 `response_model=ResponseModel[XxxOut]` 声明？
- [ ] 密钥、Token 等机密信息是否只从环境变量读取？
