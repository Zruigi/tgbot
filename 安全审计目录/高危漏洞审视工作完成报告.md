## 🔴 P0 Critical 漏洞修复详情

### 漏洞 1：凭证明文存储（CVSS 8.8）

**位置**: `config.py`  
**风险**: 管理员 Token 以明文字符串存储并直接进行字符串比较，攻击者一旦获得任意内存快照或日志即可获取完整凭证。  

**修复方案**:  
- 新增 `SecurityConfig` 类，集中管理所有安全相关配置参数  
- 新增 `verify_admin_token(token)` 函数，使用 `hashlib.sha256` + `hmac.compare_digest` 进行哈希比较，防止时序攻击  
- 支持通过环境变量 `ADMIN_TOKEN_HASH` 注入预计算哈希，兼容旧部署（自动回退到运行时动态生成）  

**修改文件**: `config.py`  
**修改内容**:
```python
# 新增
class SecurityConfig:
    ADMIN_TOKEN_HASH: str = os.getenv("ADMIN_TOKEN_HASH", ...)
    TOKEN_EXPIRY_DAYS: int = 90
    OTP_EXPIRY_SECONDS: int = 300
    MAX_LOGIN_ATTEMPTS: int = 5
    RATE_LIMIT_WINDOW: int = 60
    RATE_LIMIT_MAX_CALLS: int = 60

def verify_admin_token(token: str) -> bool:
    token_hash = hashlib.sha256(token.encode()).hexdigest()
    return hmac.compare_digest(token_hash, SecurityConfig.ADMIN_TOKEN_HASH)
```

### 漏洞 2：OTP 无一次性保证（CVSS 8.1）

**位置**: `web_admin.py`  
**风险**: 原始代码中 OTP 票据虽然在成功验证后调用了 `_otp_store.pop()`，但缺乏速率限制，攻击者可以并发暴力穷举 OTP（`token_urlsafe(24)` = 32字节熵，理论上安全，但无限制尝试仍增大风险）。  

**修复方案**:  
- 新增 `_login_rate_store` 字典和 `_check_login_rate_limit(ip)` 函数  
- `api_login_otp` 入口强制速率限制：同一 IP 在 60 秒内最多 5 次尝试，超出返回 429  
- OTP 有效期从硬编码 `300` 秒改为读取 `SecurityConfig.OTP_EXPIRY_SECONDS`  
- 登录日志中记录来源 IP  

**修改文件**: `web_admin.py`

### 漏洞 3：Token 登录无速率限制（CVSS 7.8）

**位置**: `web_admin.py` → `api_login`  
**风险**: `/api/login` 接口无任何频率限制，攻击者可无限次暴力尝试 Token。  

**修复方案**:  
- `api_login` 入口添加 `_check_login_rate_limit(client_ip)` 调用  
- 同一 IP 每分钟最多 5 次登录尝试，超出返回 HTTP 429  
- Token 校验改为调用 `config.verify_admin_token(token)` 哈希比较  

**修改文件**: `web_admin.py`

### 漏洞 4：无 CSRF 保护（CVSS 8.3）

**位置**: `web_admin.py` → 全部 POST/DELETE/PATCH/PUT 接口  
**风险**: 所有状态变更接口缺乏 CSRF 保护，攻击者可构造恶意页面诱导已登录管理员执行任意操作（群组管理、广播、监听增删等）。  

**修复方案**:  
- 新增 `_csrf_token_store` 字典和 `generate_csrf_token()` 函数，生成 32 字节随机 CSRF Token，有效期 24 小时  
- 新增 `GET /api/csrf-token` 接口，前端初始化时调用获取 Token  
- 在 `auth_middleware` 中对所有 POST/DELETE/PATCH/PUT 请求校验请求头 `X-CSRF-Token`  
- 豁免路径：`/api/login`、`/api/login/otp`、`/api/messages/`（兼容现有消息发送）  
- 本地开发环境（`127.0.0.1`）自动豁免，不影响本地调试  

**修改文件**: `web_admin.py`

### 漏洞 5：财务数据无租户隔离（CVSS 9.3）

**位置**: `finance_api.py`  
**风险**:  
- `reconcile_handler`: `admin_userid` 硬编码为 `1`，非真实认证用户  
- `reverse_handler`: `admin_userid` 直接从请求体 `data.get("admin_userid")` 获取，可被客户端任意伪造  
- `get_unreconciled_handler` / `get_summary_handler`: 接受 `user_id` 查询参数，任意用户可查询他人财务数据（IDOR）  
- `delete_monitor_handler` / `update_monitor_handler`: 无所有权校验，可操作任意 monitor  
- `add_monitor_handler`: `user_id` 从请求体获取，可伪造  

**修复方案**:  
- 新增 `_get_request_admin_id(request)` 辅助函数，统一从 `config.ADMIN_ID` 获取管理员 ID，禁止客户端传入  
- 新增 `_check_monitor_ownership(monitor_id, admin_id)` 辅助函数，校验 monitor 归属  
- `reconcile_handler`: 使用 `_get_request_admin_id()` 替换硬编码 `1`，增加 ledger 归属校验  
- `reverse_handler`: 使用 `_get_request_admin_id()` 替换 `data.get("admin_userid")`，增加 ledger 归属校验  
- `get_unreconciled_handler` / `get_summary_handler`: 移除 `user_id` 查询参数，强制使用 `_get_request_admin_id()`  
- `delete_monitor_handler` / `update_monitor_handler`: 调用 `_check_monitor_ownership()` 校验归属  
- `add_monitor_handler`: `user_id` 改为从 `_get_request_admin_id()` 获取  

**修改文件**: `finance_api.py`

### 漏洞 6：群组操作无权限检查（CVSS 8.7）

**位置**: `web_admin.py` → `api_group_member_action`、`api_group_member_action_batch`、`api_set_group_admin`、`api_demote_group_admin`  
**风险**: 攻击者可传入任意 `group_id` 操作非授权群组（BOLA/IDOR），包括禁言、踢出、设置/撤销管理员等高危操作。  

**修复方案**:  
- 新增 `_check_group_is_tracked(group_id)` 异步辅助函数，查询 `tracked_groups` 表验证群组是否在 Bot 管理范围内  
- 在以下四个函数入口添加群组归属校验，未通过返回 HTTP 403：  
  - `api_group_member_action`  
  - `api_group_member_action_batch`  
  - `api_set_group_admin`  
  - `api_demote_group_admin`  

**修改文件**: `web_admin.py`

### 漏洞 7：财务对账无原子性（CVSS 8.9）

**位置**: `finance_core.py` → `reconcile_ledger`、`reverse_ledger_entry`  
**风险**: 在高并发场景下，两个并发请求可能同时通过状态检查，导致同一条账目被双重核销或双重冲销，造成财务数据不一致。  

**修复方案**:  
- `reconcile_ledger`: 使用 `BEGIN IMMEDIATE` 获取 SQLite 写锁，确保"读取状态 → 校验 → 更新"的原子性；增加幂等保护（已 RECONCILED 的记录直接返回成功）  
- `reverse_ledger_entry`: 同样使用 `BEGIN IMMEDIATE`；增加防重复冲销保护（已 DISPUTED 的记录拒绝再次冲销）；将审计日志写入与主操作合并为同一事务，异常时统一 ROLLBACK  
- 同时修复 `create_finance_ledger` 添加 `tx_hash` 去重检查：相同 `tx_hash` 的记录直接幂等返回已有 `ledger_id`  

**修改文件**: `finance_core.py`

### 漏洞 8：金额精度无验证（CVSS 8.5）

**位置**: `finance_core.py` → `create_finance_ledger`  
**风险**: 金额直接接受 `float` 类型，浮点精度问题可能导致财务舍入误差，且无正数校验，攻击者可传入负数金额、零、或超大数值。  

**修复方案**:  
- 导入 `Decimal`、`ROUND_DOWN`、`InvalidOperation`  
- 新增 `validate_and_normalize_amount(amount)` 函数：  
  - 使用 `Decimal(str(amount))` 转换，避免浮点精度问题  
  - 校验必须为正数  
  - 校验不超过最大值 `999999999999`  
  - 使用 `ROUND_DOWN` 截断至8位小数（不四舍五入，防止财务误差）  
- `create_finance_ledger` 中对 `amount` 和 `base_fiat_value` 都调用此函数  
- 金额存储为字符串格式保留完整精度  

**修改文件**: `finance_core.py`

### 漏洞 9：地址输入无格式验证（CVSS 9.1）

**位置**: `web_admin.py` → `api_create_monitor`；`finance_api.py` → `add_monitor_handler`  
**风险**: 钱包地址未经格式校验直接写入数据库，攻击者可传入包含 SQL 注入字符、超长字符串或完全无效的地址，污染数据并可能触发下游链上查询异常。  

**修复方案**:  
- 在 `web_admin.py` 新增 `validate_wallet_address(address, network)` 函数：  
  - TRC20/TRON：正则 `^T[1-9A-HJ-NP-Za-km-z]{33}$`（34位 Base58 以 T 开头）  
  - BSC/ETH/ERC20：正则 `^0x[0-9a-fA-F]{40}$`（42位 Hex 以 0x 开头）  
  - 地址长度上限 100 字符防超长注入  
- `api_create_monitor` 在写入数据库前调用 `validate_wallet_address()`，不合法返回 HTTP 400  
- `finance_api.py` → `add_monitor_handler` 同样内嵌地址格式验证逻辑  

**修改文件**: `web_admin.py`、`finance_api.py`

**位置**: `web_admin.py` → `api_broadcast_to_chats`  
**风险**: 无频率限制，可无限次触发群发导致 Bot 被封禁或产生垃圾信息。  
**修复**: 新增 `_broadcast_rate_store` 和 `_check_broadcast_rate_limit(ip)`；同一 IP 每分钟最多 10 次广播，超出返回 HTTP 429。

## 🎯 Phase 3 前端+Low 级别漏洞修复（v4.0）

### Medium-8：localStorage Token 明文存储（CVSS 5.5）
**位置**: `frontend/src/stores/auth.ts`  
**风险**: 管理员 Token 以明文形式存储在 `localStorage`，浏览器扩展、XSS 攻击可直接读取，且 `localStorage` 跨标签页永久保留。  
**修复**:  
- 改用 `sessionStorage` 代替 `localStorage`（关闭标签页自动清除）  
- Token 存储时进行 `btoa(encodeURIComponent(token))` 混淆，防止明文直读  
- Cookie 的 `SameSite` 属性从 `Lax` 升级为 `Strict`，防止 CSRF  
- 新增迁移逻辑：检测到旧 `localStorage` 中残留 Token 时自动迁移并清理  
- 错误响应改为通用文案，不透传异常细节  
**修改文件**: `frontend/src/stores/auth.ts`

### Medium-9：WebSocket 无心跳超时清理（CVSS 5.0）
**位置**: `frontend/src/stores/ws.ts`  
**风险**: 原 ping 机制只发送心跳，但不检查 pong 响应，网络中断时僵尸连接持续占用资源，且无法触发重连。  
**修复**:  
- 新增 `pongTimeoutTimer`：每次发送 ping 后启动 60s 超时计时器  
- 60s 内未收到 pong 则调用 `ws.close()` 主动断连，触发 `onclose` 自动重连流程  
- 收到 pong 时立即清除超时计时器  
- 同步修复 Token 读取：从 `sessionStorage` 读取（配合 auth.ts 修复）  
**修改文件**: `frontend/src/stores/ws.ts`

### High-9：推送任务无权限隔离（CVSS 7.5）
**位置**: `web_admin.py` → `api_list_push_tasks`  
**风险**: `list_push_tasks()` 返回所有任务，未按管理员过滤，可泄露其他管理员的推送任务。  
**修复**: 获取列表后按 `created_by == config.ADMIN_ID` 过滤，仅返回当前管理员创建的任务。  
**修改文件**: `web_admin.py`

### Low-1：CSP report-uri 未配置（CVSS 3.0）
**位置**: `web_admin.py` → `auth_middleware` CSP 响应头  
**风险**: CSP 头未配置 `report-uri`，浏览器检测到违规时无法上报，安全团队无法感知 XSS 注入尝试。  
**修复**:  
- CSP 头末尾添加 `report-uri /api/csp-report`  
- 新增 `api_csp_report` 端点（POST `/api/csp-report`），接收浏览器上报的违规详情并写入日志  
- 路由注册表添加 `app.router.add_post('/api/csp-report', api_csp_report)`  
**修改文件**: `web_admin.py`
